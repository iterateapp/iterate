# Iterate - Cursor for PM リサーチまとめ

**プロダクト名: Iterate**

## YC RFS (Spring 2026) - Cursor for PM とは

「PMがやること（何を作るか決めること）をAIが助けるツール」。エンジニアにCursorがあるように、PMにも同じものを、というアナロジー。

YCが求めているもの：
- 顧客インタビューと使用データの**両方**を分析
- 具体的なUI変更や開発タスクまで落とし込むAIシステム

> 参照: https://www.ycombinator.com/rfs

## 競合・既存プロダクト調査

### 定量データ分析

#### Amplitude AI Feedback（2025年11月リリース）
- 20以上のソース（App Store、Zendesk、Intercom、Reddit、X等）からフィードバックを自動収集
- フィードバックを8カテゴリに自動分類（機能要望・バグ・クレーム等）
- Amplitudeの行動ログとフィードバックを紐付け
- Session Replayへの連携
- PRDドラフトの自動生成
- **制限**: 1,000文字超え不可、OpenAI依存、能動的インタビュー不可

#### Amplitude Agentic AI Analytics（2026年2月発表）
4つの専門エージェント：
1. **Dashboard Monitoring Agent** - 指標異常を数時間以内に自動検知、Slack/メール通知
2. **Session Replay Agent** - 数百セッションを自動レビュー、摩擦ポイント発見、収益インパクト定量化
3. **Web Experimentation Agent** - A/Bテスト設計・ローンチ・分析（フロントエンドの見た目変更のみ、コード変更は不可）
4. **AI Feedback Agent** - フィードバック分析 + 行動データ紐付け

連携先: Claude、ChatGPT、Cursor、Figma、Notion、GitHub

**Amplitudeの限界:**
- コードを書く・デプロイする機能はない
- A/Bテストはビジュアルエディタ経由のフロント変更のみ
- 能動的なユーザーインタビューはできない
- 「データ分析ツールの延長」であり「PMの意思決定Copilot」ではない

## 市場の空白地帯

どのプロダクトも**定量 + 定性を一体化して「次に何を作るか」まで提案するもの**はまだない。各ツールは部分最適止まり。

Amplitudeが持っていない唯一の空白：
1. **能動的にユーザーにインタビューしに行く**
2. **「何を作るか」の意思決定をPMと一緒に行う**（データ分析ではなくCopilot）

---

## Cursorの本質 = Enablement

Cursorはエンジニアを**置き換えない**。
- エンジニアが方向性を決める
- Cursorがコードを書く
- エンジニアがレビューして承認

「エンジニアが10倍速く動けるようになる」がCursorの価値。

Cursor for PMもEnablementであるべき理由：
1. PMは置き換えられない判断を持っている（会社戦略、ステークホルダーの力学）
2. 「PMの仕事を奪うAI」より「PMが10倍速く動けるツール」の方が売れる
3. YCの説明文も「proposing」= 提案、Enablement寄り

## プロダクトの方向性

### Cursorが強い本当の理由
「AIがコードを書ける」ではなく「**あなたのコードベース全体を理解している**」こと。

PM版に翻訳すると：**あなたのプロダクト全体を理解しているAI**
- 過去の意思決定を知ってる
- ユーザーセグメントの傾向を知ってる
- 前回のA/Bテスト結果を覚えてる
- 競合の動きも把握してる

### アウトプットは「判断の提案」
データでも分析でもなく、意思決定の提案まで出す：
```
🔴 優先度1: モバイルのチェックアウトフローを1ステップに短縮
  根拠: 離脱率が15%増加（Amplitude）
       インタビュー12人中9人が「ステップが多い」と回答
  推定インパクト: 月$45K の売上回復
  PRD: [自動生成済み]
  Linearチケット: [作成する？]
```

### 常時稼働・プッシュ型
PMが動くのではなく、AIが動いてPMに持ってくる：
- 常にメトリクスを監視
- 異常検知 → 自動で原因調査開始
- 必要に応じて自動でインタビュー送付
- 結論が出たらSlackでPMに通知

### PMのワークフローに住む
新しいダッシュボードではなく、既存ツールに溶け込む：
- Slackで異常検知の通知
- NotionでPRDが自動生成
- LinearにチケットがDraft状態で入る

## ハッカソンデモイメージ

1. 「モバイルの離脱率が15%上がりました」（自動検知）
2. 「Session Replayを50件分析した結果、新しい決済フローが原因の可能性が高い」
3. 「影響ユーザー20人にインタビューを送付しました」
4. 「12人が回答。9人がステップ数を指摘」
5. 「PRDを生成しました。月$45Kのインパクトが見込まれます」
6. 「Linearにチケットを作成しますか？」
